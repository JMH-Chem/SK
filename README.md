# Hackathon Agent Kit

> **한 가지만 기억:** [github.com/JMH-Chem/SK](https://github.com/JMH-Chem/SK)  
> **최우선:** 시험에 이미 존재하는 과제 `README.md`, `AGENTS.md`, 코드와 데이터는 **덮어쓰거나 삭제하지 말 것**. 이 저장소는 참고용 지침이며 과제 명세보다 우선하지 않습니다.

## 10초 사용법 — 파일 이름을 외우지 않아도 됩니다

시험 규정에 허용된 접근 방식으로 이 공개 저장소를 연 뒤 작업 AI에게 다음처럼 요청하세요.

> **"https://github.com/JMH-Chem/SK 의 지침을 읽고 작업 역할로 진행해. 시험 과제의 기존 파일은 변경·덮어쓰기 전에 충돌을 점검하고, 과제 원문 README는 보존해. 먼저 요구사항과 담당자 질문부터 정리해."**

검증 AI에게는:

> **"https://github.com/JMH-Chem/SK 의 지침을 읽고 독립 검증 역할로 진행해. 과제 README를 직접 해석하고, 작업 세션의 결과를 실제 코드와 테스트로 대조해. 코드는 수정하지 마."**

AI가 실제로 저장소 파일을 읽었는지 물어 확인하세요. 외부 접근이나 명령 실행이 제한되면 **허용된 경로만 사용**하며 우회하지 마세요.

### 안전한 파일 배치

허용된 환경에서 `git clone https://github.com/JMH-Chem/SK.git sk-agent-kit`처럼 **별도 새 폴더**에 복제하면 기존 `README.md`를 덮어쓰지 않습니다. 기존 폴더와 겹칠 경우 복제를 중단하고 다른 새 폴더를 사용하세요. 복제 후에는 `sk-agent-kit/AGENTS.md`가 상위 프로젝트에 **자동 적용되지 않으므로**, 역할별 파일을 명시적으로 읽도록 지시해야 합니다. `cp -f`, `mv`나 기존 프로젝트 루트로의 일괄 복사·덮어쓰기는 하지 마세요.


AI 코딩 도구를 활용해 **요구사항 파악 → 개발 → 독립 검증 → 인계**를 수행하는 가벼운 지침 모음입니다. 특정 대회의 문제·데이터·정답·제출물은 포함하지 않습니다.

## 세션 구성

| 세션 | 역할 |
|---|---|
| **작업 세션 (Worker)** | README 해석, 담당자 질문 생성, 구현 방식 제안, 개발, 직접 테스트, 진행 기록 |
| **검증·해설 세션 (Reviewer)** | README 독립 해석, 누락·오해 확인, 실제 코드·실행 결과 검증, 쉬운 말로 설명 |
| **별도 기록 세션은 불필요** | Worker가 과제 프로젝트 내부의 HANDOFF.md를 갱신 |

기본은 **Worker 1개 + Reviewer 1개**입니다. 서브에이전트는 환경에서 허용·지원되고 독립적인 조사가 있을 때만 사용합니다. 같은 파일을 여러 에이전트가 동시에 수정하지 않도록 합니다.

## 파일

- **AGENTS.md** — 모든 에이전트의 공통 원칙. 공식 과제 안내보다 우선하지 않음.
- **WORKER.md** — 작업 세션의 수행 절차.
- **REVIEWER.md** — 검증·해설 세션의 수행 절차. 기본적으로 읽기 전용.
- **HANDOFF_TEMPLATE.md** — 현재 과제 프로젝트에 남길 인계 문서의 양식.

## 가장 간단한 사용법

1. 공식 안내에서 공개 GitHub 자료 반입, 접근 방식, 명령 실행 허용 범위를 확인합니다.
2. 허용된 방법으로 이 저장소의 파일을 **시험 작업 환경 안에서** 읽도록 합니다. 현재 과제 원본 README를 덮어쓰지 않습니다.
3. **작업 세션**: "현재 과제 README를 먼저 확인하고 AGENTS.md와 WORKER.md를 지침으로 읽어. 분석과 담당자 질문부터 정리해 줘."
4. **검증 세션**: "과제 README를 독립적으로 분석하고 AGENTS.md와 REVIEWER.md를 읽어. 작업 세션의 해석과 구현을 검증해. 코드는 수정하지 마."
5. Worker는 HANDOFF_TEMPLATE.md를 참고하여 **과제 프로젝트 내부** HANDOFF.md를 작성·갱신합니다.

가장 먼저 **요구사항과 담당자 질문 목록**을 받아 업무 조건을 확인하고, 답을 Worker에 전달하세요. 이후 작은 작동 버전부터 구현하고, 실제 테스트 증거를 Reviewer가 확인하게 합니다.

### Git 사용이 허용되는 환경에서만

저장소를 복제하려면:

    git clone https://github.com/JMH-Chem/SK.git sk-agent-kit

복제된 폴더 안의 지침은 사용 중인 프로젝트의 루트 지침으로 자동 적용되지 않을 수 있습니다. **원래 프로젝트에 AGENTS.md가 있는지 먼저 확인**하고, 충돌 없이 적용 가능한 방법을 선택하거나 파일을 명시적으로 읽도록 지시하세요. 설치 스크립트, 모델 업데이트나 자동 권한 변경은 필요 없습니다.

## 준수 원칙

- **시험 규정 및 감독 안내 > 현재 과제 공식 README와 제출 조건 > 확인된 실무 요구사항 > 이 키트**
- 공개 저장소 활용 허용이 **모든 설치·실행 명령의 허용**을 뜻하지는 않습니다. 상세 가이드에서 확인하세요.
- 시험 문제, 제공 데이터, 작업 결과, 인증정보, HANDOFF 내용 등을 외부 GitHub에 업로드하거나 Push하지 않습니다.
- 제한된 도구·모델, 감독 프로그램, 네트워크/파일 반입 규칙을 우회하지 않습니다.
- AI가 '완료'라고 말하는 것과 실제로 테스트를 통과한 것은 다릅니다.
- 시험 중 외부 메모·채팅 열람이 제한되면 그 규정을 따르고, 허용된 작업 환경과 절차만 사용하세요.

## 핵심 기억법

**작업 AI는 만들고 기록한다. 검증 AI는 확인하고 설명한다. 사람은 담당자 답을 전달하고 대표 결과를 확인한다.**
