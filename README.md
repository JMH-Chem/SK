# SK — Hackathon Agent Kit

**이 저장소는 시험 문제를 해결하는 코드가 아니라, Codex가 과제를 분석하고 구현·검증하는 순서를 안내하는 읽기 전용 지침 모음입니다.**

> **외울 것은 주소 하나:** https://github.com/JMH-Chem/SK  
> **최우선:** 시험 규정 → 공식 과제 \`README.md\` 및 제출 조건 → 확인된 담당자 답변 → 이 저장소의 개발 방법론.
>
> **기존 과제의 \`README.md\`, \`AGENTS.md\`, 소스·데이터는 절대로 설치를 이유로 덮어쓰거나 삭제하지 않습니다.**

## AI에게 이 주소만 알려줘도 되는 이유

사용자는 별도의 설치 명령이나 지침 파일 이름을 외우지 않아도 됩니다. **허용된 시험 환경에서 Codex가 저장소를 가져올 수 있다면** 자연어 요청을 받아 다음 규칙을 스스로 수행해야 합니다.

### AI용 최초 로딩 절차 — 이 저장소를 소개받으면 순서대로

1. **시험 규정을 먼저 지킵니다.** 공개 GitHub 읽기/복제, 터미널·네트워크 사용이 허용되는지 확인합니다. 허용되지 않거나 접근에 실패하면 우회하지 말고 사용자에게 알립니다. 자동으로 성공했다고 주장하지 않습니다.
2. **현재 과제 프로젝트를 확인합니다.** 공식 과제 \`README.md\`, 기존 \`AGENTS.md\` 및 데이터·코드가 어디 있는지 파악합니다. 두 저장소의 \`README.md\`는 다른 문서입니다.
3. **이 저장소는 별도의 새 폴더(예: \`sk-agent-kit/\`)에 가져옵니다.** 과제 루트에 일괄 복사·압축 해제하거나 기존 파일을 교체하지 않습니다. 폴더가 이미 있다면 덮어쓰지 말고 내용을 먼저 확인합니다.
4. **파일을 명시적으로 읽습니다.** 첫째 이 \`README.md\`, 둘째 이 저장소의 \`AGENTS.md\`, 셋째 역할에 맞는 \`WORKER.md\` 또는 \`REVIEWER.md\`를 읽습니다. 인계가 필요하면 \`HANDOFF_TEMPLATE.md\`도 읽습니다.
5. **읽은 사실을 확인 가능하게 보고합니다.** 읽은 파일 경로, 맡을 역할, 유지할 공식 과제 \`README.md\` 경로를 짧게 알려줍니다. 실제로 읽지 못했다면 "미적용"이라고 표시합니다.
6. **역할에 맞게 진행합니다.** 사용자가 '작업'이라고 하면 Worker, '검증·리뷰·설명'이라고 하면 Reviewer입니다. 역할 지정이 없으면 기본은 Worker로 시작하되 **분석·질문 정리까지만** 합니다.
7. **모든 주요 결정의 기준은 과제 원문입니다.** 외부 지침이 필수 제출물이나 실행 조건을 바꾸지 못합니다.

**주의:** \`sk-agent-kit/AGENTS.md\`는 과제 루트의 Codex 지침으로 **자동 적용된다고 가정하지 않습니다.** Codex가 해당 파일을 직접 읽고 이 대화의 작업 방식으로 따르도록 해야 합니다. 기존 과제 루트에 \`AGENTS.md\`가 있다면 그것을 보존하고 충돌 여부를 확인합니다.

## 사용자: 처음에는 이 한마디

**작업 세션**

> \`https://github.com/JMH-Chem/SK\` 를 시험 환경에서 허용된 방식으로 **별도 폴더에 가져오고**, 저장소 README에 적힌 로딩 절차를 따라 **작업 에이전트** 역할로 진행해 줘. **기존 과제 파일은 덮어쓰지 마.** 우선 과제 README 분석과 담당자 AI에게 질문할 내용부터 알려줘.

**검증·해설 세션**

> \`https://github.com/JMH-Chem/SK\` 를 시험 환경에서 허용된 방식으로 **별도 폴더에 가져오거나 이미 가져온 폴더를 읽고**, 저장소 README에 따라 **검증 에이전트** 역할로 진행해 줘. 과제 README를 독립적으로 해석하고 작업 결과를 검증해 줘. **소스 코드를 수정하지 마.**

**작업을 이어받는 세션**

> 이 과제 프로젝트의 \`HANDOFF.md\`와 실제 코드·테스트 상태를 비교해 작업을 이어받아 줘. 기록만 믿지 말고 현재 상태를 확인해.

위 메시지는 자연어 지시입니다. GitHub 도구·터미널에 접근 가능한 AI라면 허용된 범위에서 가져오는 작업을 수행할 수 있습니다. 단순히 URL을 말한다고 모든 환경에서 **자동으로 복제·설치되는 것은 아닙니다.**

## 어떤 파일을 어떻게 참고하나요?

| 파일 | 누가 읽나 | 읽는 시점 | 하는 일 |
|---|---|---|---|
| \`README.md\` (이 저장소) | 모든 세션 | 최초 1회 | 로딩 순서·파일 경로·역할 지정 |
| \`AGENTS.md\` (이 저장소) | 모든 세션 | 역할 시작 시 | 공통 행동 규칙·검증 기준 |
| \`WORKER.md\` | 작업 세션 | 작업 시작 시 | 문제 분석 → 질문 → 개발 → 실제 테스트 → 기록 |
| \`REVIEWER.md\` | 검증·해설 세션 | 검증 시작 시 | 문제 독립 해석 → 테스트·누락 검사 → 쉽게 설명 |
| \`HANDOFF_TEMPLATE.md\` | 주로 작업 세션 | 과제 프로젝트의 기록을 처음 만들 때 | 과제 내부 \`HANDOFF.md\` 작성·갱신 양식 |

**과제에 이미 존재하는 \`README.md\`는 '무엇을 만들지'의 근거이고, 이 저장소의 문서들은 '어떻게 진행할지'에 관한 보조 지침입니다.** 지침 파일 내용은 과제 요구사항을 대체하지 않습니다.

## 세션은 기본 두 개만

- **Worker:** 기존 과제 README 조사, 담당자에게 물어볼 내용, 구현 방식 제안, 필요시 허용된 서브에이전트 활용, 구현, 실행 테스트, 과제 내부 HANDOFF 기록. 기술적 선택은 AI가 추천하고 사용자가 이해할 수 있게 설명합니다.
- **Reviewer:** 과제 원문을 독립적으로 해석해 Worker의 해석·구현과 비교하고, 실제 실행·테스트 증거를 확인합니다. 기본적으로 코드 변경은 하지 않습니다.
- 기록 전용 세션은 기본적으로 만들지 않습니다. Worker가 과제 프로젝트의 \`HANDOFF.md\`를 관리합니다.

**동시에 같은 파일을 수정하지 마세요.** 검증 세션은 Worker의 '완료' 보고보다 실제 소스와 테스트 결과를 우선합니다.

## 파일 구조 예시 — 기존 과제 파일을 보존

\`\`\`text
project/
├── README.md               # 시험 과제의 공식 원문: 보존
├── AGENTS.md               # 이미 있다면 보존
├── src/                    # 과제 코드
├── HANDOFF.md              # 필요시 과제 내부에 생성하는 작업 기록
└── sk-agent-kit/           # 외부 지침: 별도 폴더
    ├── README.md
    ├── AGENTS.md
    ├── WORKER.md
    ├── REVIEWER.md
    └── HANDOFF_TEMPLATE.md
\`\`\`

### 명령이 허용된 경우에만: 별도 폴더 복제

\`\`\`bash
git clone https://github.com/JMH-Chem/SK.git sk-agent-kit
\`\`\`

이 명령을 사용자가 외울 필요는 없습니다. **AI에게 자연어로 가져와 달라고 요청하면 되고**, AI가 실제 도구·권한이 있는 경우에만 실행할 수 있습니다. 작업 위치와 동일 이름 폴더 존재 여부를 먼저 확인해야 합니다.

## 시험 규정·보안

- 공개 자료 활용이 허용되어도 설치 스크립트 실행·외부 네트워크·파일 이동이 전부 허용되는 것은 아닙니다.
- 개인 컴퓨터에 있는 과제 자료, 시험의 문제·데이터·코드·HANDOFF·결과를 GitHub로 업로드하거나 Git Push하지 않습니다.
- 외부 결과물로 과제 전체를 대체하거나 모델/도구 제한·감독·권한 설정을 우회하지 않습니다.
- 시험 환경에서 외부 메모·채팅 열람이 제한되면 그 규정을 따릅니다.
- 사용한 외부 공개 자료의 공개 유지 기간, 반입 방법은 **해당 시험의 최신 공식 지침**을 따릅니다.

**한 줄 정리:** GitHub 주소 전달 → AI가 별도 폴더에서 지침 읽기 → 과제 README로 개발 → 다른 세션으로 독립 검증.
